## 문서화 원칙

### 1. 즉시 기록
- 작업 중 발견한 중요한 사항은 즉시 기록합니다.
- 작업 완료 후 기억에 의존하지 않습니다.

### 2. 상세하게 기록
- 코드 변경 이유를 명확히 기록합니다.
- 설계 결정 사항과 그 배경을 문서화합니다.
- 에러나 버그의 원인과 해결 과정을 상세히 기록합니다.

### 3. 검색 가능하게 작성
- 적절한 제목과 태그를 사용합니다.
- 관련 문서에 링크를 추가합니다.
- 인덱스 문서를 활용합니다.

### 4. 유지보수 가능하게 작성
- 정기적으로 문서를 업데이트합니다.
- 오래된 정보는 명확히 표시합니다.
- 문서 구조를 일관되게 유지합니다.

## 작업 문서화 프로세스

### 1단계: 작업 시작 전

#### 작업 세션 로그 생성
1. `docs/worklog/WORK_SESSION_LOG.md`에 새로운 작업 세션 항목 추가
2. 작업 목표 및 범위 정의
3. 관련 파일 목록 작성
4. 예상 작업 시간 기록

#### 테스크 분해 (복잡한 작업의 경우)
1. `docs/worklog/TASK_MANAGEMENT.md`에 테스크 목록 생성
2. 테스크 간 의존성 파악
3. 우선순위 설정
4. 각 테스크에 예상 소요 시간 기록

### 2단계: 작업 중

#### 실시간 기록
- 코드 변경 시 변경 이유 기록
- 발견한 이슈 즉시 기록
- 중요한 결정 사항 문서화
- 설계 변경 사항 기록

#### 프로그램 로직 상세 기록
- 복잡한 로직은 `docs/worklog/DETAILED_LOGIC_TEMPLATE.md` 형식으로 기록
- 함수/클래스별 상세 설명 작성
- 데이터 흐름 다이어그램 작성 (필요시)

### 3단계: 작업 완료 후

#### 작업 세션 로그 업데이트
1. 작업 내용 요약 작성
2. 테스트 결과 기록
3. 발견한 이슈 및 해결 방법 기록
4. 다음 작업 항목 작성

#### 관련 문서 업데이트
1. `PROGRAM_LOGIC.md` 업데이트 (프로그램 로직 변경 시)
2. `REFACTORING_GUIDE.md` 업데이트 (리팩토링 시)
3. `BUG_FIX_LOG.md` 업데이트 (버그 수정 시)
4. `ERROR_PATTERNS.md` 업데이트 (새로운 에러 패턴 발견 시)

#### 인덱스 업데이트
1. `WORKLOG_INDEX.md`에 새 문서 링크 추가
2. 관련 문서 간 링크 추가

## 문서 유형별 가이드

### 1. 작업 세션 로그
**파일**: `docs/worklog/WORK_SESSION_LOG.md`

**용도**: 각 작업 세션의 전체 내역을 기록

**포함 내용**:
- 작업 목표 및 범위
- 작업 내용 상세
- 발견한 이슈 및 해결 방법
- 테스트 결과
- 다음 작업 항목

### 2. 프로그램 로직 상세 기록
**파일**: `docs/worklog/DETAILED_LOGIC_TEMPLATE.md` 또는 새 파일 생성

**용도**: 복잡한 로직의 상세한 설명

**포함 내용**:
- 함수/클래스 개요
- 입력/출력 설명
- 처리 흐름
- 에러 처리
- 사용 예시
- 관련 파일

### 3. 버그 해결 로그
**파일**: `docs/worklog/BUG_FIX_LOG.md`

**용도**: 버그 발견 및 해결 과정 기록

**포함 내용**:
- 버그 증상
- 원인 분석
- 해결 방법
- 관련 파일
- 예방 조치

### 4. 리팩토링 가이드
**파일**: `docs/worklog/REFACTORING_GUIDE.md`

**용도**: 리팩토링 가이드 및 베스트 프랙티스

**포함 내용**:
- 리팩토링 원칙
- 코드 구조 가이드
- 리팩토링 체크리스트
- 일반적인 리팩토링 패턴

### 5. 테스크 관리
**파일**: `docs/worklog/TASK_MANAGEMENT.md`

**용도**: 복잡한 작업을 세분화된 테스크로 관리

**포함 내용**:
- 테스크 목록
- 테스크 간 의존성
- 우선순위
- 진행 상황

## 예시

### 예시 1: 간단한 버그 수정

```markdown
### [2024-12-XX] workspace 객체 누락 버그 수정

**작업 일자**: 2024-12-XX
**작업 시간**: 14:00 - 15:30
**상태**: 완료

**작업 목표**:
- workspace 객체가 없을 때 발생하는 오류 수정
- 방어 코드 추가로 안정성 향상

**작업 범위**:
- `js/ui/workspaceMode.js`
- `js/ui/kanbanMode.js`
- `background.js`

**작업 내용**:
1. workspaceMode.js의 renderWorkspace 함수에 방어 코드 추가
   - ideaData.workspace 객체 자체를 안전하게 초기화
   - 하위 속성들(keywords, outline, draft, linkedScraps) 기본값 할당
   - 관련 파일: `js/ui/workspaceMode.js`

2. kanbanMode.js에 2차 안전 장치 추가
   - 카드 클릭 핸들러에서 renderWorkspace 호출 전 workspace 객체 보장
   - 관련 파일: `js/ui/kanbanMode.js`

3. background.js의 createAndSaveNewIdea 함수 보강
   - workspace 객체 생성 로직 명확화
   - 관련 파일: `background.js`

**발견한 이슈**:
- 기존 데이터에 workspace가 없어도 정상 작동하도록 하위 호환성 고려 필요
- 해결: 기존 필드와 workspace 객체 동기화 로직 추가

**테스트 결과**:
- workspace 객체 없을 때 정상 작동: ✅ 통과
- 기존 데이터 호환성: ✅ 통과

**다음 작업**:
- 다른 모드에서도 workspace 객체 보장 확인

**관련 문서**:
- [버그 해결 로그](./BUG_FIX_LOG.md#workspace-객체-누락-버그)
```

### 예시 2: 복잡한 기능 추가

```markdown
### [2024-12-XX] AI 브리핑 자동 생성 기능 추가

**작업 일자**: 2024-12-XX
**작업 시간**: 10:00 - 18:00
**상태**: 완료

**작업 목표**:
- 아이디어 저장 시 AI 브리핑 데이터 자동 생성
- 추천 목차, 추천 검색어, 롱테일 키워드 자동 생성

**작업 범위**:
- `background.js` (AI API 호출)
- `js/services/aiService.js` (프롬프트 생성)
- `js/ui/workspaceMode.js` (UI 업데이트)

**작업 내용**:
1. background.js에 브리핑 생성 로직 추가
   - 아이디어 저장 시 자동으로 브리핑 생성 요청
   - 병렬 처리로 성능 최적화
   - 관련 파일: `background.js`

2. aiService.js에 브리핑 프롬프트 생성 함수 추가
   - 추천 목차 생성 프롬프트
   - 추천 검색어 생성 프롬프트
   - 롱테일 키워드 생성 프롬프트
   - 관련 파일: `js/services/aiService.js`

3. workspaceMode.js에 브리핑 데이터 표시 로직 추가
   - Firebase 실시간 리스너로 자동 업데이트
   - 진행률 표시 추가
   - 관련 파일: `js/ui/workspaceMode.js`

**발견한 이슈**:
- 브리핑 생성 실패 시 재시도 로직 필요
- 해결: 지수 백오프 재시도 로직 추가

**테스트 결과**:
- 브리핑 자동 생성: ✅ 통과
- 실시간 업데이트: ✅ 통과
- 재시도 로직: ✅ 통과

**다음 작업**:
- 브리핑 데이터 수동 재생성 버튼 추가
- 브리핑 데이터 편집 기능

**관련 문서**:
- [프로그램 로직 - AI 서비스](./PROGRAM_LOGIC.md#ai-서비스)
- [AI 서비스 가이드](../guides/AI_SERVICE_GUIDE.md)
```
