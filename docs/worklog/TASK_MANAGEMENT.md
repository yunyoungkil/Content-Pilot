## 테스크 관리 원칙

### 1. 작은 단위로 분해
- 각 테스크는 1-4시간 내에 완료 가능한 크기로 분해합니다.
- 테스크가 너무 크면 더 작은 단위로 나눕니다.

### 2. 명확한 목표
- 각 테스크는 명확한 목표와 완료 조건을 가져야 합니다.
- "완료"의 기준이 명확해야 합니다.

### 3. 의존성 관리
- 테스크 간 의존성을 명확히 파악합니다.
- 의존성이 있는 테스크는 순서대로 진행합니다.

### 4. 우선순위 설정
- P0: 긴급 (즉시 처리 필요)
- P1: 높음 (가능한 빨리 처리)
- P2: 보통 (일반적인 우선순위)
- P3: 낮음 (시간 있을 때 처리)

## 테스크 분해 방법

### 1단계: 큰 작업을 기능 단위로 분해
```
큰 작업
  ├─ 기능 1
  ├─ 기능 2
  └─ 기능 3
```

### 2단계: 각 기능을 구현 단계로 분해
```
기능 1
  ├─ 데이터 모델 설계
  ├─ API 구현
  ├─ UI 구현
  └─ 테스트
```

### 3단계: 각 구현 단계를 세부 테스크로 분해
```
API 구현
  ├─ 엔드포인트 정의
  ├─ 비즈니스 로직 구현
  ├─ 에러 처리
  └─ 문서화
```

## 테스크 진행 상황

### 진행 중인 테스크
- 테스크 1-1: 작업 환경 설정 (진행 중, 50% 완료)

### 완료된 테스크
- 없음

### 보류된 테스크
- 없음

### 차단된 테스크
- 테스크 2-2: API 구현 (테스크 2-1 완료 대기 중)

## 테스크 기록 형식

각 테스크는 다음 형식으로 기록합니다:

```markdown
- [ ] 테스크명: 간단한 설명
  - **우선순위**: P0/P1/P2/P3
  - **예상 시간**: X시간
  - **의존성**: 테스크 ID 또는 없음
  - **담당자**: (선택사항)
  - **상태**: 대기 중 / 진행 중 / 완료 / 보류
  - **시작일**: YYYY-MM-DD (선택사항)
  - **완료일**: YYYY-MM-DD (선택사항)
  - **관련 파일**: `파일 경로` (선택사항)
  - **참고**: 추가 참고 사항 (선택사항)
```

## 테스크 관리 팁

### 1. 테스크 크기 조절
- 테스크가 너무 크면 (4시간 이상) 더 작은 단위로 나눕니다.
- 테스크가 너무 작으면 (30분 이하) 관련 테스크와 합칩니다.

### 2. 의존성 관리
- 의존성이 있는 테스크는 명확히 표시합니다.
- 의존성이 해결되면 즉시 다음 테스크를 시작합니다.

### 3. 우선순위 조정
- 작업 진행 중 우선순위가 변경될 수 있습니다.
- 변경 시 즉시 업데이트합니다.

### 4. 진행 상황 추적
- 정기적으로 진행 상황을 업데이트합니다.
- 완료된 테스크는 체크박스를 체크하고 완료일을 기록합니다.
